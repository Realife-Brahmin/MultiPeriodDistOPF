# IEEE123C: FilterDDP versus IPOPT matrix handling

Measured on `ieee123C_1ph`, `T = 3`, using the same exported network data.
The FilterDDP snapshot is one deliberately capped iteration (three backward
stages), not a new convergence run. The IPOPT statistics come from the
centralized JuMP model generated by
`ddp/examples/power_system/ieee123c_ipopt_matrix_diagnostic.jl`.

| Property | FilterDDP | IPOPT |
|---|---|---|
| Matrix solved | Stage saddle-point matrix `K = [Hhat cu'; cu 0]` | Global barrier primal-dual KKT matrix, conceptually `[W+D J'; J -R]` |
| One global or stagewise? | One system at each stage of every backward pass | One global space-time system per Newton step |
| Dimensions at `T = 3` | Three `1353 x 1353` systems: `nu + nc = 791 + 562` | Conceptual primal/constraint system `3678 x 3678`: 1992 variables + 1305 equalities + 381 inequalities |
| Sparse or dense in code? | `SparseMatrixCSC`; 4506 nonzeros at terminal stage and 7056 at stages 2 and 1 (0.246% and 0.385% density) | Sparse Jacobian/Hessian supplied to IPOPT: 6438 Jacobian nonzeros and 1296 Lagrangian-Hessian nonzeros |
| Factorization | Julia `lu(K)`, which dispatches to UMFPACK | MUMPS 5.9.0 sparse symmetric-indefinite solver |
| Main scaling variable | Stage size `nu+nc`, plus dense sensitivity width `nx+1` and dense `nx x nx` value Hessian | Global horizon-wide variables and constraints, hence approximately linear dimensions in `T` before fill-in |

## Exact FilterDDP code path

The constrained sparse solve is at
`ddp/external/FilterDDP.jl/src/backward_pass.jl:128-138`:

- line 133 constructs sparse `K = [Hhat cu'; cu 0]`;
- line 134 explicitly densifies the multiple right-hand side with `Matrix(...)`;
- line 137 performs `lu(K) \ rhs`.

The code never calls `Matrix(K)`. It therefore preserves sparsity in the KKT
coefficient. It does **not** preserve sparsity throughout the backward pass:
the right-hand side is dense with size `1353 x 52`, because it simultaneously
solves for the feedforward direction and all `nx = 51` state sensitivities.
The returned `beta` and `omega` blocks are dense.

The measured stage details were:

| Stage | `nnz(Hhat)` | `nnz(cu)` | `nnz(K)` | `nnz(L)+nnz(U)` | LU fill ratio |
|---:|---:|---:|---:|---:|---:|
| 3 | 536 | 1985 | 4506 | 9562 | 2.122 |
| 2 | 3086 | 1985 | 7056 | 19963 | 2.829 |
| 1 | 3086 | 1985 | 7056 | 19933 | 2.825 |

The key event occurs immediately after the terminal-stage elimination:
`Vxx` changes from an all-zero `51 x 51` matrix to a fully dense matrix with
2601 nonzeros. It remains fully dense at the earlier stages. Because the
dynamics Jacobian selects the 51 battery controls, this dense value Hessian
adds a dense `51 x 51` battery block to `Hhat`; that is why `nnz(Hhat)` rises
from 536 to 3086. Thus IEEE123 confirms the proposed concern: a sparse feeder
KKT matrix survives, but the DDP Schur-complement/value recursion creates dense
intertemporal information inside it.

## IPOPT facts

The centralized run used IPOPT 3.14.19 with MUMPS 5.9.0 and reported:

- 1992 variables;
- 1305 equality and 381 inequality constraints;
- 4914 equality-Jacobian plus 1524 inequality-Jacobian nonzeros;
- 1296 Lagrangian-Hessian nonzeros;
- 34 Newton iterations and objective `2808.924651221923`, matching the stored
  centralized reference;
- 0.143 s wall time in `ComputeSearchDirection` out of 0.188 s total IPOPT
  algorithm time; 0.014 s symbolic-factorization and 0.044 s backsolve wall
  time were separately exposed.

IPOPT does not expose the final MUMPS factor nonzero count in this ordinary
log, so this run does not support a numerical IPOPT fill-ratio claim. Its
advantage here is consistent with a mature global sparse NLP path—ordering,
scaling, regularization, and an indefinite solver—not with a simplistic
"IPOPT sparse, FilterDDP dense" distinction. FilterDDP's coefficient is also
sparse. Its distinctive costs are repeated stage factorizations, a dense
`nx+1`-column right-hand side, and dense value-function curvature generated by
elimination.

The raw IPOPT header and timing output are retained in
`ddp/results/network_filterddp/ieee123C_1ph_ipopt_T3_matrix.log`.
