# Reduced-space MPOPF: consolidated findings, 2026-09-14 / 15

Self-contained summary for an outside reader. Everything below was measured in
this repository over two days. Sections are marked **ESTABLISHED**,
**RETRACTED**, or **OPEN / HYPOTHESIS** — the distinction matters, because
several confident claims made during the work turned out to be wrong and are
recorded here rather than quietly dropped.

---

## 1. Setting

Multi-period optimal power flow for a distribution feeder with batteries and PV,
using the branch-flow (BFM/DistFlow) SOCP relaxation. Horizon `T`, timestep
`dt = 24/T` hours.

```
min   sum_t [ c^t · S · dt · P_Subs^t  +  C_B · S² · dt · ‖P_B^t‖² ]
s.t.  B^t = B^{t-1} − dt · P_B^t                     (battery dynamics)
      g_t(y^t, P_B^t) = 0                             (balance, voltage drop, SOC)
      y^t ∈ Y_t                                       (v box, ℓ≥0, |q_norm|≤1,
                                                       P_Subs≥0, soc_slack≥0)
      P_B^t ∈ [−P_B_R, P_B_R],  B^t ∈ [B_min, B_max]
```

`y^t` = every algebraic network variable. `S` = 1000 kVA base.

**Solver**: FilterDDP (Xu et al., arXiv 2504.08278 / 2606.01487) — a
second-order differential dynamic programming method with an interior-point
barrier and a filter line search. Its backward pass solves a sparse `nu×nu` KKT
system per stage.

**The idea under test**: eliminate the network. Define the *reduced stage value*
by partial minimisation at fixed battery dispatch,

```
Φ_t(P_B) = min_y { c^t · S · dt · P_Subs : g_t(y, P_B) = 0, y ∈ Y_t }
```

and let FilterDDP optimise only over battery quantities:

```
state   x = B^t            (nx = nB)
control u = [P_B^t ; s_E^t] (nu = 2·nB)
stage   l_t = Φ_t(P_B^t) + C_B·S²·dt·‖P_B^t‖²
```

Each `Φ_t` evaluation is an Ipopt solve of a single-period OPF. Motivation is
dimensionality:

| system | buses | batteries | full-space `nu` | reduced `nu` |
|---|---|---|---|---|
| ieee123C_1ph | 128 | 51 | 791 | 102 |
| ieee2522C_1ph | 2522 | 249 | 13358 | 498 |
| large10kC_1ph | 10321 | 1020 | 54665 | 2040 |

Nothing in the FilterDDP solver source was modified. Its `Objective`,
`Dynamics` and `EqualityConstraints` are plain structs over six callables, so
the OCP is assembled from hand-written closures — which is also forced, since an
Ipopt solve is not automatically differentiable.

## 2. ESTABLISHED results

### 2.1 The elimination is exact

Partial minimisation is exact, and this was verified against stored full-space
FilterDDP solutions:

| system (T=3) | reduced vs full-space objective |
|---|---|
| ieee123 | `6.0e-09` relative |
| ieee2522 | `1.3e-08` relative |
| large10k | `4.33e-10` relative, max ‖ΔP_B‖ = `6.0e-11` pu (0.0000 kW) |

### 2.2 The gradient is free and exact

By the envelope theorem, `dΦ_t/dP_B,b = λ_b`, the dual of the real-power balance
row at battery bus `b` — available from every inner solve at no cost.

Verified by central differences with a step-size study, on the system that later
fails (ieee2522, T=12):

| configuration | best relative error |
|---|---|
| cold inner solves, ρ=0 | **`1.5e-11`** |
| cold inner solves, ρ=1e4 | **`1.0e-09`** |
| warm-started inner solves | `3.0e-04` … `3.0e-03` |

### 2.3 Warm starting corrupts the VALUE, not the gradient

The warm-start error follows a clean `1/h` law (`3.020e-05`, `3.020e-04`,
`3.020e-03` at `h` = 1e-3, 1e-4, 1e-5) — the signature of a **constant absolute
error ≈ 8.7e-6 USD in Φ**. The duals match cold solves to nine digits.

This matters because FilterDDP's filter accepts or rejects steps by comparing
*values*. (Whether it is causally implicated in the failure of §4 is **not**
established — per-step decreases near the breakdown are ~1e-2, three orders
larger.)

### 2.4 Structure of `∇²Φ`

Measured by finite differences on the duals (`nB` solves per stage):

| | nB | eigenvalue range | effective rank @1% | ideal rank-25 error |
|---|---|---|---|---|
| ieee123 T=3 | 51 | 1.19 … 2482 | 36 | 2.6% |
| ieee2522 T=3 | 249 | −0.148 … 21194 | **59** | 2.3% |

Key properties:

- **Dense and not low-rank**, but the required rank does **not** grow with system
  size (51→249 batteries; rank 36→59). A randomised Nyström sketch of ~65 probes
  reproduces the ieee2522 Hessian to 2.74%.
- **Diagonal is useless**: 94% relative error, only 33% of the Frobenius mass.
- **Nearly constant**: 1.1% relative change between the initial point and the
  optimum, 2.6% between stages, 6.3% at a 70%-of-rating outlier — *all measured
  at T=3*, see §3.1.
- `H·d` for any direction costs exactly **one** inner solve, so randomised
  methods apply directly.

### 2.5 `C_B` controls the conditioning of the entire curvature model

The stage Hessian is `∇²Φ + 2·C_B·S²·dt·I`. The second term is perfectly
conditioned damping; `C_B` sets how much of it sits under the network curvature.
On ieee2522 (`∇²Φ` spanning −0.148 … 21194):

| `C_B` | battery diagonal | cond(∇²l) |
|---|---|---|
| **1.4e-07** (what the exported data actually uses) | **2.24** | **10,131** |
| 1e-05 | 160 | 134 |
| 1e-03 | 16,000 | 2.32 |
| 0.05 | 800,000 | 1.03 |

At `C_B = 1.4e-07` there is effectively **no damping** — `∇²Φ` *is* the whole
curvature model — and every cheap curvature approximation fails:

| curvature model | result at `C_B`=1.4e-07 |
|---|---|
| exact, frozen once per stage | converges |
| Nyström low-rank (rank 50+15) | **stalls at iteration cap** |
| Nyström low-rank + eigenvalue floor | **stalls** (dual residual 16× better but still ~6e-4) |
| battery term only (`2.24·I`) | **stalls** |

Raise `C_B` to 1e-3 and the same low-rank sketch converges. Mechanism: a
direction whose true curvature is 21194 modelled as 2.24 yields a Newton step
**9,463× too long**.

**Sizing rule** (measurement-based, no per-system tuning): `2·C_B·S²·dt` must
exceed `−λ_min(∇²Φ)` for positive definiteness, and `≈ λ_max/κ` sets the
condition number. `λ_max` costs ~10 inner solves by power iteration.

**`C_B` conditioning is `dt`-invariant**: `Φ ∝ dt` so `∇²Φ ∝ dt`, and the damping
`∝ dt` too — the ratio is `dt`-free, so one `C_B` per system works at any `T`.

### 2.6 Feasibility of the battery box

`F_t` = the set of battery dispatches the network can serve.

- **The box is NOT recourse-feasible in general.** 111 structured + random
  dispatches: ieee123 accepts 111/111; ieee2522 rejects 8/111, all by
  undervoltage under charging.
- **`F_t` is not a function of aggregate battery power** — a pattern with
  `sum(P_B) = −0.017` pu (essentially zero net) is still infeasible.
- **`F_t` is horizon-independent.** The inner problem is a single snapshot with
  no reference to `t±1`, `B^{t-1}` or `T`. Verified: three slots at identical net
  load across different `T` return identical verdicts and identical violation
  (`v0 = 7.81`).
- **No scalar load index is a sufficient statistic.** Difficulty is monotone in
  neither net nor gross load, because high-PV hours have the highest *gross* load
  and lose 45% of DER reactive headroom (`q_max = √(S_D_R² − p_D²)`).

### 2.7 Feasibility cuts are valid

At an infeasible dispatch, solving a pure-feasibility inner problem
(minimise violation only) and linearising gives `v0 + gᵀ(P_B − P_B⁰) ≤ 0`, with
`g` the balance duals. Since the inner problem is convex, this is a global
under-estimator.

| check | result |
|---|---|
| cuts excluding a hard-feasible dispatch | **0 of 168** |
| margin at the closest feasible dispatch | −4.54 (median −71.7) |
| other infeasible dispatches also excluded | **13 of 30 (43%)** |
| gradient vs central differences | `6.9e-07` |

**Never yet exercised by a real run** (see §4).

### 2.8 Substation-bus resources are inert

ieee2522 carried one battery and one PV at the substation bus. The BFM root rows
are `P_Subs − Σ P_out` and `Q_Subs − Σ Q_out`, carrying no local resource term,
so such units contribute nothing while occupying a control variable, a bound and
an SOC row; their `dΦ/dP_B` is identically zero. Removal verified **bit-exact**
(Φ identical to `0.000e+00` over three random dispatches). Removed from the
source OpenDSS files; ieee2522 now has 249 batteries and 249 PV.

## 3. RETRACTED / corrected claims

### 3.1 Every `T = 3` result is on a degenerate instance — the big one

The profile generator sampled `sin` at `range(0, 2π, length=T)`. At `T=3` that
lands on `0, π, 2π` — all zero — so **the price is exactly constant** and the
instance carries no arbitrage signal at all.

| instance | price spread | max ‖P_B‖ / rating |
|---|---|---|
| large10k T=3 | **0.0%** | **0.054 – 0.057** |
| ieee2522 T=3 | 0.0% | 0.16 – 0.26 |
| ieee123 T=3 | 0.0% | 0.16 – 0.33 |
| ieee2522 T=12 | 147.3% | 0.009 – **0.971** |

Consequences:

- The **2.07× large10k speedup was measured with the batteries essentially
  idle** (5% of rating). Valid timing on that instance; **not** evidence the
  decomposition works on a real scheduling problem.
- Every other `T=3` success — 13-iteration convergence, the frozen Hessian
  holding up, zero infeasible dispatches, the crossover table — is on the same
  degenerate family. With `P_B` pinned near zero the active set never moves,
  which is exactly the easy case.
- **It reframes the `T≥12` failures.** They were read as "the method breaks at
  longer horizons", but horizon was confounded with *whether the battery does
  anything*. `T=12` is the first instance with a real price signal, hence the
  first genuine test — and the method fails it.

Secondary defect in the same expression: `range(0, 2π, length=T)` includes both
endpoints, so samples 1 and `T` share a phase at **every** `T`.

Fixed by opt-in periodic sampling (phase `2π(k−1)/T`, price spread 118% at
`T=3`), writing to its own filename. The exporter now prints price/load/PV
spreads on every run, warns below 5%, and records `:profile_periodic` and
`:price_spread` inside each instance.

### 3.2 "The reduced space does 465× less work per iteration" — wrong

That came from comparing `nu³`, i.e. assuming a dense backward pass. Measured
per-iteration cost scales like `nu^1.3` (123→2522) and `nu^1.85` (2522→10k). A
dense factorisation at large10k would need 22.3 GB per stage and ~540 s against
2.25 s measured — the production backward pass is sparse. The theoretical
advantage was much smaller than claimed.

### 3.3 "~6% Hessian error is tolerable" — wrong

Inferred from `frozen` working while the Hessian drifts 1.1–6.3% between points.
That does not follow: smooth drift perturbs the whole matrix consistently, while
low-rank truncation zeroes *specific directions*, and a Newton model with no
curvature along a direction takes an unbounded step there.

### 3.4 "`C_B` conditioning is T-invariant, so behaviour is T-invariant" — wrong

The algebra is right (§2.5) and all three `C_B` values fail identically at T=12,
which confirms it. But `T`-invariant *conditioning* does not imply `T`-invariant
*behaviour*; a separate mechanism scales with horizon.

## 4. The OPEN problem: the method fails once the battery actually cycles

### 4.1 What fails

ieee2522, `T=12` and `T=24`, all three `C_B` values, 200-iteration cap:

| | full-space | reduced |
|---|---|---|
| T=12 (all `C_B`) | 542–545 s, 78 it, **converged** | 2692–3857 s, 200 it, **failed** |
| T=24, `C_B`=1e-5 | 1112 s, 84 it, **converged** | 3989 s, 200 it, **failed** |

Dual residuals `1.0e+01` … `1.6e+04`. Full space is unaffected throughout.

### 4.2 The trace (this is the key evidence)

ieee2522, T=12, `C_B`=1e-3:

```
iter   objective        du_inf       cs_inf     lg(μ)   alpha
   0   9.16353349e+03   4.8089e+02   8.3002e-03   0.00
  13   8.57830272e+03   9.1360e-02   8.0418e-03  -3.49    1.0
  14   8.57829614e+03   9.1888e-03   8.0001e-03  -3.49    1.0   ← best point
  15   8.56980773e+03   3.2424e+00   4.6208e-03  -3.49    0.5   ← breaks
  21   8.56076846e+03   2.8367e+01   3.2000e-04  -3.49    1.0
  23   8.56076308e+03   2.6451e+01   3.2000e-04  -3.49    1.0
```

- `du_inf` falls **four orders of magnitude in 14 iterations**, then jumps three
  and oscillates between 1 and 28.
- The objective is flat in its fifth digit from iteration 17; final gap to
  full-space is `2.7e-05`. **The iterate is essentially at the solution and
  cannot certify it.**
- `lg(μ)` is pinned at −3.49 with `cs_inf` exactly equal to `μ`. FilterDDP only
  tightens its barrier once dual infeasibility is small enough; once `du_inf`
  bounces above that gate it can never tighten again. **That is why it is fatal
  rather than merely slow.**

### 4.3 Remedies tried and eliminated

| attempt | result |
|---|---|
| fixed ρ instead of adaptive (single-valued objective) | dual 13.7 → 11.1; still fails |
| distance-triggered Hessian re-sketching | dual → 15.3; drove infeasible evals to **0**; still fails |
| ⇒ therefore the **L1 penalty kink is NOT the cause** | zero evaluations entered the nonsmooth region, and it still failed |
| barrier smoothing of the inner problem (`mu_target`=1e-4) | fails; see §4.5 for why the test may be under-powered |
| exact (non-sketched) frozen Hessian at T=12 | **never completed** — run was killed; genuinely untested |

### 4.4 Current best hypothesis — NOT verified

`Φ_t` is **`C¹` but only piecewise `C²`**.

The envelope theorem gives `∇Φ = λ` under LICQ, strict complementarity and a
locally constant active set. Let `P_B` move so a bound in `Y_t` changes status
(a voltage limit, an inverter reactive limit). Then:

- `Φ_t` stays convex ✓
- `∇Φ_t` stays continuous ✓
- **`∇²Φ_t` is discontinuous across the active-set boundary** ✗

That is exactly the wrong regularity for a second-order method: the gradient is
sound, but the Hessian is valid only on one side of a surface the step can
cross. The active set is large and dispatch-dependent — `|q_norm| = 1.0` at
33–51 of 51 DERs in every ieee123 solve — so every outer step reshuffles it.

This explains the sudden break at iteration 15, why exact and low-rank curvature
behave alike (both exact within a region, neither valid across one), and why the
measured `λ_min = −0.148` looked like noise (a finite difference taken *across*
a boundary is not a second derivative).

**It has never been directly tested.** The obvious test — instrument the inner
solves to record which bounds are active, and check whether the set changes at
exactly the iteration where `du_inf` jumps — has not been run.

### 4.5 Why the barrier-smoothing test was probably under-powered

The implied remedy is to keep the inner barrier open: with `μ > 0` no inequality
is ever active, `Φ^μ` is `C^∞`, and `Φ^μ → Φ` as `μ → 0`.

Tested with `μ_inner = 1e-4` and it failed. But the **outer** barrier at the
time sat at `lg(μ) = −2.10`, i.e. `μ_outer ≈ 8e-3` — the inner problem was
**80× sharper than the outer**, so at the outer method's own resolution the
active set was still effectively fully resolved. The right setting is
`μ_inner ≳ μ_outer` (ideally coupled so both tighten together). That re-run has
not been done.

Two implementation traps found while building that test, both of which produced
convincing-looking failures that meant nothing:

- `tol` must scale with `mu_target`: Ipopt's NLP error includes complementarity,
  pinned at `~μ`, so `tol=1e-10` at `μ=1e-4` is unsatisfiable and surfaces as
  `SLOW_PROGRESS` (5 of 12 stages silently returned a failure sentinel).
- If `Φ^μ` is the barrier problem's value, its gradient is the barrier problem's
  dual, so the reported **value must include** `−μ·Σlog(slack)`, or the outer
  method gets an inconsistent value/gradient pair.

## 5. Timing picture (all on the degenerate `T=3` instances — see §3.1)

`C_B = 1e-3`, both formulations re-run at the same `C_B`:

| | full-space | reduced (low-rank) | outcome |
|---|---|---|---|
| ieee123 (`nu` 791→102) | 14.4 s / 46 it | 21.7 s / 26 it | 1.5× slower |
| ieee2522 (`nu` 13358→498) | 107.3 s / 56 it | 107.1 s / 33 it | parity |
| large10k (`nu` 54665→2040) | 1690 s / 100 it | 802 s / 13 it | 2.07× faster |

Trends worth noting even though the instances are weak: outer iteration counts
move in **opposite directions** with system size (full-space 46/56/100, reduced
26/33/13), because the reduced dimension is set by battery count rather than
network size; and the bottleneck migrates — inner solves are ~70% of wall at
ieee123 but 25% at large10k.

Engineering that made the reduced side viable at all: warm-started inner solves
(~35 interior-point iterations → ~6) and a persistent JuMP model updated via
`set_normalized_rhs` instead of rebuilt per call (together ~4× on the inner
workload).

## 6. Open questions

1. **Is the piecewise-`C²` diagnosis correct?** Direct test: record the active
   set at each inner solve and check whether it changes at the iteration where
   `du_inf` jumps. Untested.
2. **Does barrier smoothing work with `μ_inner ≳ μ_outer`?** The one test used
   `μ_inner` 80× *sharper* than the outer barrier.
3. **Is there a principled way to couple the inner and outer barriers?**
   FilterDDP exposes no hook for its current `μ`.
4. **Does the method converge on a non-degenerate `T=3` instance?** If it fails
   there too, the debug loop shrinks from an hour to minutes — and it would show
   the problem is battery activity, not horizon.
5. **Would feasibility cuts help?** They are validated as *objects* (§2.7) but
   never wired into the outer loop, which would keep the inner problem
   hard-constrained and the objective a single smooth `Φ` on `F_t`.
6. **Is a second-order method the right tool at all?** A nested value function is
   generically only piecewise smooth. Bundle or semismooth methods handle that
   natively; FilterDDP does not.

---

## 7. One-line summary

The network can be eliminated exactly and its gradient is free and verified to
`1e-11`; the resulting reduced problem converges when the batteries barely move
and fails as soon as they genuinely cycle, for reasons not yet established — and
the apparent large-system speedup was measured on instances with no price signal
at all.
